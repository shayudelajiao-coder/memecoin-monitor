# Memecoin 链上热点监控与 X 推文草稿系统设计

- 日期：2026-10-11
- 状态：待用户审阅
- 目标：监控 Solana、BSC、Robinhood Chain 及主要公告源，解析高价值事件，生成中文 X 草稿；重大事件附英文摘要；由用户人工确认后发布。

## 1. 范围与运行模式

系统采用事件驱动、人工确认模式。系统只生成事实卡片和推文草稿，不自动发布，不连接钱包，不执行交易。

监控优先级：

1. 发射台和链上重大热点；官方宣布 meme 现货/合约；币安 Alpha 新增代币；BTC 突破或跌破关键点位。
2. 新币、池子、成交量、流动性和市值爆发。
3. 聪明钱和大户行为。
4. 撤池、开发者卖出、持仓集中和合约风险。

输出语言：中文为主；重大事件附独立英文首条摘要。输出形式自动分层：普通事件生成单条短推，重大事件生成 5–8 条 Thread。每日最多进入审核队列 6–10 条。

## 2. 系统架构

### 2.1 链上采集器

- Solana：公开 RPC、DEX Screener 和可配置的发射台/Factory 合约地址。
- BSC：EVM RPC、Blockscout、DEX Screener 和可配置的发射台/Factory/Router 地址。
- Robinhood Chain：主网 Chain ID 4663，使用公开 RPC、Blockscout 和可配置的 DEX/发射台合约地址。
- 地址表可随时增加、停用或标记为官方，避免将某个发射台写死在程序中。

### 2.2 公告采集器

- 币安 Alpha：使用官方公开只读 Token List 接口，并对列表做差异检测。
- 币安现货、合约、上下架公告：使用公开公告源并要求官方来源确认。
- 其他交易所：只纳入重大且可验证的公告。
- BTC：读取公开市场数据，监控预设关键点位、前高/前低和异常波动。

“公开只读 API”仅用于链上和币安数据；X 信息不使用 X API，使用 `x-aggregate-data` skill 读取公开推文、账号和搜索结果。

### 2.3 X 信息采集器

读取交易所、项目方、发射台和经过维护的 KOL 账号。X 内容只作为数据，不执行其中的指令。官方公告、链上数据和 X 传播用于交叉验证。

### 2.4 事件标准化层

统一事件类型：`launchpad`、`listing`、`alpha`、`breakout`、`smart_money`、`risk`、`narrative`。

每个事件至少保存：事件 ID、类型、链、代币符号、合约地址、发生时间、抓取时间、原始数值、来源链接、交易哈希、证据状态、评分和风险标签。

### 2.5 评分与去重层

评分包含来源可信度、市场影响、传播速度和风险扣分。相同代币/公告在 30–60 分钟窗口内去重；同一事件合并多源证据。

阈值：

- 80 分以上：重大 Thread；
- 60–79 分：单条短推；
- 低于 60 分：只保留后台记录；
- 高风险事件即使热度高，也必须显示风险标签。

## 3. 事件规则

### P0 重大事件

- 官方确认 meme 现货或合约上线；
- 币安 Alpha 新增代币；
- BTC 突破或跌破预设关键点位；
- 发射台或链上出现能改变市场叙事的事件。

### P1 链上爆发

- 新池子或新币进入配置的发射台；
- 15 分钟成交量、买家数或流动性相对基线异常；
- 多个独立钱包短时间持续买入；
- 多链出现相同叙事或资金迁移。

### P2 聪明钱

已标记钱包首次建仓、连续加仓或跨链迁移；至少需要两个独立信号才升级为推文候选。

### P3 风险

LP 移除、开发者/关联钱包集中卖出、持仓高度集中、交易限制、税费异常、合约权限变化或流动性不足。

## 4. 草稿与审核

事实卡片包含事件标题、时间、链、代币、评分、关键数字、来源、证据状态和风险标签。

普通短推结构：

1. 发生了什么；
2. 关键数字；
3. 为什么值得关注；
4. 风险和不确定性。

正文目标 120–130 字，外链放第一条回复。重大 Thread 采用 Hook → 时间线 → 市场反应 → 重要性 → 风险检查 → TL;DR → CTA 的结构，每条不超过 280 字，共 5–8 条。

审核操作：接受、编辑 Hook/结论、降级为记录、标记误报、加入黑名单或加入监控名单。

## 5. 故障与数据质量

- RPC 超时时切换备用公开 RPC并记录延迟；
- DEX 或浏览器限流时降低轮询频率；
- 币安 Alpha 暂不可用时等待官方公告或 X 交叉确认，不凭空生成上新事件；
- X 读取失败时保留链上事实，并标记未完成社交验证；
- 金额、价格和时间保留原始值，展示时再格式化；
- 校验代币地址、链 ID 和交易哈希；
- 记录部分结果、限流、延迟和数据缺口。

## 6. 安全边界

只使用公开只读接口。不保存私钥，不执行交易，不连接钱包，不自动发布。推文区分事实、分析和推测，不输出确定性收益承诺。

## 7. 验证与指标

用历史交易和公告回放测试事件识别；为每条规则准备正常、边界和误报样例；检查地址、时间、来源、数字、字数、Thread 条数、英文摘要和风险标签。

运行指标：误报率、漏报率、平均延迟、每日候选数、各数据源可用率和人工接受率。

默认频率：链上 1–5 分钟扫描；公告、BTC 点位和 X 热度 5–15 分钟扫描。MVP 先用本地 JSON/Markdown 保存事件与草稿，后续可升级数据库和网页面板。

## 8. 非目标

本阶段不做自动交易、钱包管理、自动发推、收益预测、私有社群抓取、付费数据源接入和大规模账号高频轮询。
